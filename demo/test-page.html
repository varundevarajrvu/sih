SIH 26171 -- Phase 4 integration demo page

Static page exercising every PII-detection path the extension's loop needs to prove: an input[type=password], an input[type=email], an "ID card" bearing a real human face (COCO-80 has no "ID card" class -- the face is what lets the vision half of this demo fire at all), a plain type=text field holding an autofilled Aadhaar-shaped value with NO type/autocomplete signal (the specific false-negative case Phase 2a's dom-scanner was hardened against), and one genuinely benign, actionable field + button so the mock VLM backend has something safe to act on. See demo/README.md for how to run the loop against this page.

Account sign-in (DOM-flagged fields)

Flagged via type=password + autocomplete=current-password. Must never appear in the outgoing DOM JSON.

Flagged via type=email + autocomplete=email.

Plain type=text, no autocomplete attribute -- the field itself gives dom-scanner zero type/autocomplete signal. Only flagged because its value is Aadhaar-shaped (12 digits). This is the autofilled-PII false-negative case Phase 2a was specifically hardened against; vision alone can never catch this one, since it's never rendered as a face or a screen -- only the DOM scan does.
