How to read this page

Every PII element below is labeled with what SHOULD happen to it. The thin dashed lines running across the whole page (with numbers on the left, e.g. 1200px) are a fixed ruler -- they always show distance from the TOP of your current browser window, which is the exact coordinate space bboxes live in. Green badges are read directly off the live DOM's own attributes (data-agent-id, data-agent-sensitive, data-sih-closed-shadow) by this page's own script -- genuinely independent confirmation, not a restatement of anything the extension prints. Dark geo-readout boxes show this page's own, independently computed "expected" geometry for the iframe cases, for you to compare by eye against the ruler.

After running the loop, open the PAGE's console (not the popup, not the service worker) for the RUN SUMMARY -- see demo/README.md's new TIER 1 section for the exact fields to read (framesReported, framesMerged, framesDropped, subframeSensitiveNodes, subframeActionableNodes, unscannableRegions) and what each PASS/FAILURE combination means.

3. Closed Shadow DOM (top frame) -- the completely unverified path

attachShadow({mode:"closed"}). dom-scanner.js can NEVER see inside this -- element.shadowRoot reads back null for closed mode, patch or no patch, always. The only way this gets caught at all is shadow-detect.js's MAIN-world attachShadow patch marking the host with data-sih-closed-shadow BEFORE this card's own attachShadow() call (below) ever runs. CLAUDE.md records this exact mechanism as completely unverified in a real browser -- this is the single highest-value thing on this page to check.

If the patch fired: the badge below turns green, this host is counted in unscannableRegions, and the WHOLE card gets defensively blacked out in the redacted screenshot (the entire host, not just text -- nothing inside a closed root can be individually located, so the whole thing is the redaction unit). If the patch did NOT fire: the badge stays gray forever, this host is invisible to every scan, and -- because closed- shadow content still renders on screen even though script cannot read it -- the real, readable PII text below would be sent to the VLM unredacted, inside the screenshot, with zero console error. That silent failure mode is exactly the hole TIER 1 closes, and exactly why it needs a real browser to confirm.

Declared limitations (CLAUDE.md TIER 1) -- not bugs, do not mistake these for failures:

  • Only ONE level of iframe nesting is supported. Iframe-inside-iframe is out of scope for this pass -- not exercised on this page.
  • CSS transform: scale on an <iframe> element is NOT compensated (position offset only). This page never applies a transform to either iframe, on purpose.
  • assertNoRawPii cannot check subframe nodes against live element references from the top frame -- each subframe runs its own sanitize + leak check before its report ever leaves that frame's isolated world instead (see scanThisFrame() in content.js).
